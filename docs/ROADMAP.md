# 로드맵

> 기준일: 2026-08-17

전통시장을 지원하는 사용자 모바일 앱, 운영자 웹과 API로 확장하는 순서를 정의합니다. 2단계 이후의 미션과 보상 예시는 방향을 보여 주기 위한 것이며 확정된 정책이 아닙니다.

## 0단계 — 문서화와 개발 기반

**목표:** 현재 상태를 잃지 않고 누구나 재현 가능한 모노레포 기반을 준비합니다.

- 제품 이야기, 프로젝트 상태, 개발 방법과 아키텍처 문서화
- 추적 가능한 앱 설정 템플릿과 민감 설정 주입 방식 마련
- 루트 npm workspaces 구성
- `mobile/`을 `apps/mobile/`로 기능 변화 없이 이동
- 공통 계약, 지오펜스, 시장 데이터와 설정 패키지 생성
- 루트와 모바일에 중복된 기존 시장 JSON을 검증된 GeoJSON으로 한 번만 이관
- 타입 검사와 단위 테스트를 실행하는 기본 CI 구성

**완료 기준:** 새 clone에서 문서만으로 Android 개발 빌드를 재현하고, 앱 이동 전후의 기존 Polygon 기능이 동일하게 동작해야 합니다.

## 1단계 — 대전 전통시장 지오펜스 MVP

**목표:** 하나의 전통시장을 첫 사례로 검증하고, 같은 코드와 데이터 계약으로 대전의 다른 전통시장을 추가할 수 있게 합니다.

- 등록된 전통시장 경계 표시 기능의 실기기 검증
- 시장 데이터 유효성 검사와 단일 원본 적용
- 지역별 시장 카탈로그와 안정된 시장 ID 도입
- `packages/geo`의 순수 Point-in-Polygon·MultiPolygon 판정 구현
- GPS 좌표를 내부, 외부, 확인 중, 권한 없음, 위치 오류 상태로 표현
- 중심점, 외부점, 경계선, 꼭짓점과 잘못된 Polygon 단위 테스트
- Emulator 모의 위치와 실제 기기에서 시장 안팎 이동 시나리오 검증
- 두 번째 대전 전통시장 데이터를 추가해 단일 시장 하드코딩이 없는지 검증
- 위치 갱신 주기, 정확도와 배터리 사용 정책 결정

**완료 기준:** 동일한 좌표와 시장 경계는 항상 같은 결과를 내고, 경계 좌표는 내부로 처리되며, 데이터 추가만으로 두 개 이상의 대전 시장을 선택·표시·판정할 수 있어야 합니다. 사용자에게 판정 불가 상태를 내부·외부로 오인해 보여 주지 않습니다.

## 2단계 — 서비스 최소 기반

**목표:** 모바일에서 시작한 참여를 API가 검증하고 운영자가 관리할 수 있게 합니다.

- 사용자, 시장, Polygon, 미션, 진행도와 리워드의 최소 계약 정의
- 인증과 권한 경계 수립
- 앱의 참여 증거 제출과 API의 서버 권위 검증
- 중복 발급을 방지하는 리워드 원장
- 시장 구역, 미션과 보상 상태를 관리하는 최소 운영자 화면
- 감사 로그, 오류 추적과 기본 운영 지표

**완료 기준:** 운영자가 하나의 시장과 미션을 게시하고, 사용자가 모바일에서 참여하며, API가 검증된 완료 건에만 리워드를 한 번 발급해야 합니다.

백엔드 프레임워크, 관리자 웹 프레임워크, 데이터베이스, 인증 제공자는 이 단계 착수 전 ADR로 결정합니다.

## 3단계 — 확장형 미션

**목표:** 시장 방문을 걷기, 구매와 함께하는 경험으로 확장합니다.

- 시장 구역 안에서 일정 걸음 수 달성
- 지정 가게 구매 확인
- 친구 또는 그룹 동반 방문
- 기간, 횟수, 대상 매장과 사용자 조건을 조합하는 미션 운영
- 센서 조작, 위치 위조, 영수증 재사용과 중복 참여 대응

**완료 기준:** 미션 종류별 증거와 검증 방식이 분리되어 새 미션을 추가할 때 기존 미션 계약을 깨지 않아야 합니다.

구매 확인 방식, 친구 관계 모델과 부정 참여 판정 기준은 실제 운영 파트너와 요구사항을 확인한 뒤 결정합니다.

## 4단계 — 지역 보상 생태계

**목표:** 디지털 참여를 시장과 지역에 의미 있는 보상으로 연결합니다.

- 온누리상품권 포인트 등 외부 보상 연동 가능성 검토
- 지역 홍보대사 친필 사인과 한정 기념품 같은 재고형 보상
- 시장·상인·지자체·협력사별 예산과 재고 관리
- 캠페인 성과와 재방문 지표를 확인하는 운영 리포트
- 여러 전통시장으로 확장 가능한 시장 등록과 데이터 검수 절차

**완료 기준:** 보상마다 발급 주체, 비용, 재고, 사용 조건과 정산 근거가 추적되어야 합니다.

외부 포인트 연동, 정산, 개인정보와 법적 요구사항은 계약과 정책 검토가 끝난 뒤 별도 ADR 및 운영 문서로 확정합니다.

## 확정된 방향과 보류된 결정

### 확정

- 사용자 Expo 앱, 운영자 웹, API를 하나의 저장소에서 관리
- npm workspaces와 `apps/`, `packages/` 구조 사용
- 지오펜스 로직과 시장 데이터를 공유 패키지로 분리
- 모바일은 안내를 제공하고 API가 미션 완료와 리워드 발급의 최종 권한을 보유

### 후속 ADR에서 결정

- API와 관리자 웹의 프레임워크
- 데이터베이스와 배포 플랫폼
- 인증 및 사용자 관계 모델
- 위치·센서 증거 보관 기간과 개인정보 정책
- 구매·동반 방문 검증 방식과 부정 참여 방지 정책
- 보상 사업자 연동, 재고, 정산과 법적 요구사항
